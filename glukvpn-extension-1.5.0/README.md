# GlukVPN — расширение для браузера

Расширение для Chrome / Edge / Brave / Opera / Yandex / Vivaldi. Тот же аккаунт,
тот же control-server, тот же дизайн, что у мобильного приложения. Устройство
появляется в базе как браузер, а не как `android`.

```
extension/                    само расширение (его и грузим в браузер)
server/glukvpn-browser-proxy/ шлюз, который ставится на немецкий узел
```

---

## 1. Установка расширения

1. Распакуйте архив.
2. Откройте `chrome://extensions` (в Edge — `edge://extensions`).
3. Включите **Режим разработчика**.
4. **Загрузить распакованное расширение** → выберите папку `extension`.
5. Откроется панель GlukVPN. Войдите тем же логином, что в приложении.

При входе расширение само:

- генерирует пару ключей X25519 (приватный не покидает браузер);
- регистрирует устройство через `POST /api/devices/register`;
- поднимает сессию через `POST /api/vpn/connect`;
- переключает трафик браузера на шлюз узла.

Есть два интерфейса: попап на иконке (телефонный вид) и полная панель —
иконка «Дашборд» в попапе или *Параметры* у расширения. Панель сделана
квадратной консолью, как на присланном скрине.

## 2. Обязательный шаг: шлюз на узле

**Расширение браузера физически не может поднять WireGuard.** У страницы нет
ни raw UDP, ни TUN-устройства — это ограничение самих браузеров, не кода.
Единственный настоящий API маршрутизации в MV3 — `chrome.proxy`.

Поэтому схема такая:

```
браузер ──TLS CONNECT──> glukvpn-browser-proxy (немецкий узел) ──> интернет
   │                              │
   │  Basic: deviceId:accessToken │ проверяет токен через GET /api/vpn/status
   ▼                              ▼
   аккаунт, устройство, сессия ── control-server (без изменений)
```

Без шлюза расширение установится, залогинится и создаст устройство и сессию в
базе, но трафик пойдёт напрямую. Разворачивается шлюз за пару минут:
`server/glukvpn-browser-proxy/deploy/README.md`.

После установки шлюза укажите его в *Settings → Browser gateway*:
хост (имя из сертификата, например `de-01.gluk.tech`), порт `8443`, схема HTTPS.
Если поле хоста пустое, берётся хост самого узла из `/api/nodes` —
это сработает только если сертификат выписан на это имя.

> Изменений в control-server и в схеме БД не требуется. Шлюз использует только
> существующие эндпоинты.

## 3. Что видно в базе

`POST /api/devices/register` присылает реальный браузер, поэтому в таблице
`devices` появляется:

| Поле | Значение |
| --- | --- |
| `platform` | `chrome`, `edge`, `brave`, `opera`, `yandex`, `vivaldi`, `chromium` |
| `deviceName` | `Chrome 141 - Windows`, `Edge 141 - macOS` и т.п. |
| `publicKey` | настоящий X25519, приватная часть только в `chrome.storage.local` |

Браузер определяется по `navigator.userAgentData.brands` с откатом на User-Agent,
причём Edge/Opera/Yandex/Vivaldi/Brave проверяются раньше Chrome — иначе все они
опознались бы как Chrome.

Сессия, `assignedVpnIp`, `bytesRx`/`bytesTx` и закрытие сессии идут через штатные
`/api/vpn/connect`, `/api/vpn/status`, `/api/vpn/disconnect`.

## 4. Дизайн

Всё взято из вашего кода, не придумано:

- токены цветов, радиусы, градиенты и тайминги — `flutter-client/lib/theme/tokens.dart`
  и `site/assets/css/tokens.css` (`--bg #0a0714`, `--violet #8b5cf6`,
  `--green #4fd88c`, `--grad-cta`, `--ease-soft` и т.д.);
- стеклянные панели, аврора-фон, кнопка питания с ореолом, строки серверов,
  переключатели — `site/assets/css/app-ui.css`;
- точечная карта мира с пунктирной дугой — как на сайте: равнопромежуточная
  проекция, тот же viewBox 119×60, точки на треугольной решётке.

Два отличия, о которых честно стоит знать:

1. **Шрифт.** Poppins/Nunito в расширение не вкладывались, чтобы не тащить
   бинарники: используется системный стек (`Segoe UI Variable`, `system-ui`).
   Если нужен точный шрифт — положите `.woff2` в `extension/ui/` и поменяйте
   `--font` в `theme.css`.
2. **Данные карты.** MCP-сервер во время сборки отвалился (502/530), файл
   `site/assets/js/world-dots.js` дочитать не удалось, поэтому маска материков
   сгенерирована заново в той же проекции и с той же решёткой (2013 точек).
   Стилистически идентично; если хотите байт-в-байт тот же файл — скопируйте
   `packed` из сайта и замените его в `extension/lib/world-dots.js`
   (формат там описан в комментарии).

Подписи в интерфейсе английские — как на присланном макете и в HTML-шаблоне.
Все строки лежат в `ui/popup.js` и `ui/dashboard.js`, на русский меняются в одном месте.

## 5. Настройки

| Настройка | Смысл |
| --- | --- |
| Channel | `prod` (`api.gluk.tech`) или `beta` (`beta-api.gluk.tech`) |
| Browser gateway | хост/порт/схема шлюза на узле |
| Kill switch | при недоступном шлюзе трафик блокируется, а не утекает напрямую |
| Bypass list | что ходит мимо туннеля (по умолчанию localhost и локальные сети) |
| Connect on browser start | поднимать туннель при запуске браузера |
| Account devices | список устройств аккаунта, можно отозвать лишние |

## 6. Ограничения

- **Один туннель на аккаунт.** В схеме `max_concurrent_sessions` по умолчанию `1`,
  поэтому при активном туннеле на телефоне `/api/vpn/connect` вернёт 409, и
  расширение честно скажет об этом. Варианты: отключить телефон, поднять лимит
  пользователю или поставить на шлюзе `REQUIRE_SESSION=false`.
- **Лимит устройств.** `maxDevices` по умолчанию 3; браузер занимает слот.
  Повторный вход с того же браузера слот не съедает — срабатывает
  `device.reregister` по тому же публичному ключу.
- **Firefox не поддерживается** в этой версии: там нужен `browser.proxy.onRequest`
  вместо PAC + `webRequestAuthProvider`. Основа кода переносится, но манифест и
  слой прокси нужно писать отдельно.
- **Только HTTP/HTTPS-трафик браузера.** Прокси не уводит UDP, QUIC, WebRTC и
  трафик других программ. QUIC браузер сам отключает при активном прокси, а для
  WebRTC полезно дополнительно поставить
  `chrome://flags` → *Anonymize local IPs exposed by WebRTC*.
- Самоподписанный сертификат на шлюзе не подойдёт: браузер молча отвергнет
  HTTPS-прокси. Нужен нормальный сертификат (certbot).

## 7. Структура

```
extension/
  manifest.json          MV3, минимум Chrome 108 (нужен webRequestAuthProvider)
  background.js          service worker: сессия, устройство, опрос, прокси
  lib/api.js             клиент control-server, refresh в один поток
  lib/proxy.js           PAC-скрипт и chrome.proxy
  lib/x25519.js          генерация ключей WireGuard (проверено против Node crypto)
  lib/browser.js         определение браузера -> platform для базы
  lib/store.js           chrome.storage + настройки по умолчанию
  lib/format.js          байты, время, пинг, флаги
  lib/geo.js             города/страны -> координаты для карты
  lib/world-dots.js      точечная карта мира
  ui/theme.css           токены и компоненты из приложения и сайта
  ui/popup.html|.js      попап 380×560
  ui/dashboard.html|.js  квадратная панель: VPN / Servers / Settings
  ui/world.js            отрисовка карты и анимация дуги
  icons/                 16/32/48/128
server/glukvpn-browser-proxy/
  src/server.js          TLS CONNECT шлюз, проверка токена, счётчики трафика
  .env.example           настройки
  deploy/                systemd-юнит и инструкция
```
