### 1. Архитектура и структура репозитория
Проект состоит из 5 взаимосвязанных компонентов:
1. `flutter-client/` — единый клиент для Android и Windows Desktop на Flutter 3.24.
   - Android: системный VPN API через плагин WireGuard.
   - Windows: юзерспейс WireGuard (`wintun.dll` + `glukvpn-wg.exe`), сборщик Inno Setup через `desktop/packaging/build-all.ps1`.
2. `control-server/` — Fastify + Prisma + PostgreSQL (TypeScript).
   - Боевой порт 8081 (`glukvpn-control`), бета-порт 8082 (`glukvpn-beta-control`).
3. `site/` — статический фронтенд (чистый HTML, CSS, JS) на `/var/www/vpn.gluk.tech/`.
4. `glukvpn-extension-1.5.0/` — расширение Chrome (Manifest V3, проксирование и управление туннелем).
5. `docs/` — архитектурная документация (`docs/api.md`, `docs/traffic-integrity.md`, `docs/ru-blocking.md`).

### 2. Текущее состояние кодовой базы (ветка `desktop/beta`)
Актуальная версия экосистемы: **2.1.0 (build 7)**.
Что уже полностью сделано и протестировано:

**Внеплановая задача (отказ банка по магазину TabPay).** Две причины отказа — реклама обхода блокировок и то, что оплата не приводила к выдаче подписки. Сделано четырьмя коммитами:
- **Тексты сайта:** с главных и `/features` (RU + EN) убраны формулировки про обход блокировок и самореферентные фразы-заглушки вроде «это не стоковые картинки». Юридические тексты в `/terms` и секция «Чего VPN не делает» оставлены намеренно.
- **Поздние сеттлементы:** `reconcilePendingOrders` перепроверяет не только PENDING, но и FAILED/CANCELLED за последние 24 часа, оживляя их через `markOrderPaid({ revive: true })`.
- **Возврат от шлюза:** `site/assets/js/app.js` разбирает `?paid=1` / `?failed=1`, дёргает `POST /api/billing/orders/sync` (5 попыток раз в 3 с) и называет один из трёх исходов: ожидание, отклонено, подключено. Параметры стираются, чтобы F5 не повторял сообщение.
- **Регистрация без Telegram:** флаг `REGISTER_REQUIRE_TELEGRAM` (по умолчанию `false`). Аккаунт создаётся сразу после кода из письма и остаётся неподтверждённым (`telegramVerifiedAt = null`); привязка — позже в кабинете той же ручкой, что и смена Telegram. `/api/auth/config` теперь различает `telegram.enabled` и `telegram.required`. Контракт — `docs/api.md`, раздел «Регистрация».
  - ⚠️ Пробный период (`TRIAL_OFFER_REQUIRE_TELEGRAM`, по умолчанию `true`) по-прежнему требует подтверждённого аккаунта — это сознательно: отказ от шага должен стоить регистраций, а не денег. Если владелец хочет иначе — это отдельное решение.

- ⚠️ Тесты, сборка, typecheck и миграция `20260913120000_user_support_flag` **не запускались** — в песочнице нет ни npm, ни Flutter SDK. ### 3. Рабочий процесс и правила работы (КРИТИЧНО)
1. **Ветка:** вся работа ведётся строго в ветке `desktop/beta`. Все коммиты должны быть атомарными и с понятными сообщениями (`feat(...)`, `fix(...)`).
2. **Второй агент:** тесты, сборка бинарников (`.exe`, `.apk`), пуш в `origin` и деплой на боевой сервер (`138.2.186.223`) выполняются парным агентом (Antigravity). Твоя задача — писать чистый, корректный код без синтаксических и логических ошибок.
3. **Строгие инварианты (НЕ ЛОМАТЬ):**
   - В `control-server/src/services/entitlements.ts` переменная `FREE_PLAN` должна иметь явную типизацию `: PlanShape` (из-за `noUncheckedIndexedAccess`).
   - На сайте `dashboard.css?v=20260909.1` зафиксирован тестом `site/tests/site.test.cjs` — там же пинятся порядок подключения скриптов и существование всех ассетов из HTML. Не менять версию без обновления теста; весь JS в `site/assets/js/` обязан оставаться ES5 (тест парсит файлы через `new vm.Script`).
   - В `desktop_home_screen.dart` класс `_MapCard` является `StatelessWidget`, объект `auth: widget.auth` передаётся в него через конструктор (не обращаться через `widget.auth` внутри `_MapCard`).
   - Публичные контракты JS: `window.GlukAuth`, `planBadge`, `sprint2.js`.
   - Роли персонала: записи для support — только allow-list `SUPPORT_ALLOWED_WRITES` в `routes/admin.ts`. Новая ручка под `/api/admin/*` по умолчанию admin-only; не переписывать гейт в deny-list и не возвращать `requireAdmin` на весь файл (сейчас там `requireStaff`).
   - В `control-server/public/admin.js` любая мутирующая кнопка рисуется только под `canManage()`, флаги `state.isAdmin` / `state.isSupport` сбрасываются в `signOut()`, а `loadAll()` не грузит саппорту admin-only разделы: 403 в общем `Promise.all` выбрасывает из панели.
   - При добавлении колонок в таблицу пользователей обновлять `colSpan` заглушек (сейчас 10) и `<th>` в `public/index.html`.
   - Цвет шкал квоты и бюджета считается в JS одними и теми же функциями (`quotaHue` / `quotaFill` / `quotaColor`; во Flutter — `QuotaScale` в `lib/theme/tokens.dart`). Не возвращать градиенты зелёный→синий/фиолетовый и пороговые классы (`.warm`, `.is-warn/.is-high/.is-crit`): в CSS оставлены только одноцветные fallback'и на случай выключенного JS.
   - Палитра трафика едина на всех площадках: `#3ddc97` — получено клиентом (download), `#c4b5fd` — отправлено (upload). `.s2-trend`, `.s2-peak`, линии маршрутов и `.dash-bar` — другой смысл, их цвета под эту палитру не выравнивать.
   - Не трогать глобальные настройки Nginx и не включать UFW на сервере.
