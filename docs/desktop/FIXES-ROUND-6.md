## 1. Главное: туннель переведён на Wintun (WHQL)

**Что было.** `wireguard.dll` (WireGuard-NT) — это загрузчик ядерного драйвера без
WHQL-подписи Microsoft. На Windows с включённой «Изоляцией ядра» / Memory
Integrity / WDAC ядро отклоняет `WireGuardCreateAdapter` с `ERROR_ACCESS_DENIED (5)`.
В логе это выглядело как `Tunnel worker starting (driver unavailable)` и `ok=0, ran 0s`,
а в UI — как `tunnel_service_unavailable` / `tunnel_error`. То есть на вашем ПК туннель
не мог подняться ни при каких настройках клиента.

**Что стало.** Ядро — официальный WHQL-подписанный `wintun.dll` 0.14.1, тот же,
что у Proton, Mullvad и остальных.

| Файл | Изменение |
| --- | --- |
| `src/wireguard_nt.h` | Прежние типы WireGuard-NT убраны; контракт `PeerStats` / `ReadPeerStats` сохранён, чтобы `tunnel.cpp` не переписывать. |
| `src/wireguard_nt.cpp` | Полностью новый: загрузка `wintun.dll` + клиент WireGuard UAPI по именованному каналу (`get=1`), оттуда rx/tx и last handshake. |
| `src/tunnel.cpp` | `DriverReady()` проверяет `tunnel.dll` + `wintun.dll`; `DriverDescription()` → `wintun`; понятные тексты ошибок. |
| `CMakeLists.txt` | Копирует `tunnel.dll` и `wintun.dll` (без `wireguard.dll`). |
| `build-all.ps1` | Скачивает `wintun-0.14.1.zip` обязательно (не «если получится»), `tunnel.dll` собирается с бекендом wintun. |
| `build-desktop.yml` | То же в CI. |
| `installer.iss` | В установщик кладётся `wintun.dll`. |

Критерий приёмки: на чистой Windows с включённой «Изоляцией ядра» — установил,
нажал Connect, в сетевых адаптерах появляется Wintun-адаптер GlukVPN. Никакие
сторонние программы ставить не нужно.

## 2. Единый вход по ссылке (как в GeForce NOW)

Раньше было три разных способа войти, два из них — костыли. Теперь это
стандартный device authorization grant.

**Новые эндпоинты** (`control-server/src/routes/link.ts`, хранилище — `services/linkAuth.ts`):

| Метод | Зачем |
| --- | --- |
| `POST /api/auth/link/start` | Клиент создаёт запрос, получает `userCode`, `pollSecret` и `verifyUrl`. |
| `POST /api/auth/link/poll` | Клиент ждёт подтверждения. Все состояния — обычные 200. |
| `GET /api/auth/link/:code` | Сайт показывает, что именно подтверждается. Требует входа. |
| `POST /api/auth/link/:code/approve` | Выдаёт токены. Аудит `auth.link.approved`. |
| `POST /api/auth/link/:code/deny` | «Это не я». Аудит `auth.link.denied`. |

Граница доверия, из-за которой это безопасно: `userCode` едет в URL и сам по себе
ничего не даёт — превратить его в токены может только живая сессия на сайте, а
забрать их — только тот, у кого есть `pollSecret`, который никогда не покидает
процесс клиента. `pollSecret` хранится только как SHA-256 и сравнивается
`timingSafeEqual`; токены одноразовые, ссылка живёт 10 минут.

**Сторона сайта:** новые `site/link/` и `site/en/link/` + `site/assets/js/link.js`.
Карточка показывает приложение, имя устройства и код, и даёт две кнопки:
«Войти» и «Это не я». Если браузер открылся без кода — код можно ввести руками.

**Сторона ПК:** `AuthController.signInWithLink()` — одна точка входа для всех
клиентов; после одобрения сразу вызывается `ensureDeviceRegistered()`, так что
сессия сразу становится device-scoped. На экране видно код и кнопка «Отмена».

Осталось по этому пункту: расширение ещё использует старый мост
(`call('linkWithSite')` + ожидание токена от content-скрипта). Перевод его на те же
три эндпоинта требует правок в service worker — следующий шаг.

## 3. Устройства больше не накапливаются

На скрине было «Устройства 48 / 3». Причина — выход помечал строку как
`REVOKED`, а не удалял её.

- `POST /api/auth/logout` теперь удаляет запись устройства (или все при `allDevices`).
  Сессии и refresh-токены уходят каскадом, аудит пишется до удаления.
  Если удалить не вышло — падаем обратно в `REVOKED`, токены всё равно мертвы.
- `DELETE /api/devices/:id` тоже удаляет; аудит переименован в `device.remove`.
- Кнопка «Отозвать» → «Выйти».
- Имя устройства — реальное: на Windows `Platform.localHostname` (например `ALISHER-PC`),
  на Android — `getprop ro.product.brand/model` (например `Pixel 7`). Без новых
  зависимостей; при любой ошибке — старая общая метка.

## 4. Аккаунт — отдельный экран

`lib/desktop/screens/desktop_account_screen.dart` (новый). Карточка аккаунта в
сайдбаре теперы открывает его, а не настройки. По образцу `#view-profile` из
расширения:

- шапка с аватаром, номером аккаунта, e-mail и гео;
- сетка фактов: Тариф / Действует до / Устройства / Сессий сразу;
- группировка устройств сегментами с счётчиками (Все / Активные / Вышли);
- иконки по платформе (`lib/widgets/device_icon.dart`, общие с телефоном);
- подтверждение перед выходом; кнопка «Выйти» — тихая, не во всю ширину.
