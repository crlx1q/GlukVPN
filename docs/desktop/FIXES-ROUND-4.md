# Desktop round 4 - fixes

Everything below is on branch `desktop/beta`. Android and the browser extension
are untouched.

## 1. Only one client per machine

`lib/desktop/services/single_instance.dart` (new).

A named kernel mutex (`Global\GlukVPN.Desktop.SingleInstance`) is claimed in
`main()` before `windowManager.ensureInitialized()`, so a second copy never even
flashes a window. When the mutex already exists the second process finds the
running window (`FindWindowW` on the Flutter runner class), restores and focuses
it, shows a localised "GlukVPN is already running" message box, and exits.

Why a mutex and not a lock file or a port: the kernel releases it when the
process dies, so a crash can never leave the user locked out, and `Global\`
scope also covers fast user switching.

A failure inside the guard returns "you are the first instance". A cosmetic
protection must never be able to stop the client from starting.

## 2. The red strip along the top of the window

`lib/desktop/services/window_fx.dart`.

That was the Windows accent colour painting the window frame and caption. The
previous code asked DWM for `DWMWA_COLOR_NONE` (0xFFFFFFFE); when Windows
refuses that value - older builds, or "Show accent colour on title bars and
window borders" enabled - it falls back to the accent colour, which on this
machine is red.

Fixed by setting explicit dark `COLORREF`s that personalisation cannot
override:

| attribute | value |
| --- | --- |
| `DWMWA_BORDER_COLOR` (34) | `#16121F` (main), `#0B0813` (tray panel) |
| `DWMWA_CAPTION_COLOR` (35) | `#08060F` (main), `#0B0813` (tray panel) |
| `DWMWA_TEXT_COLOR` (36) | `#F5F3FB` |

## 3. Smaller, fixed window; bigger button; fuller map

- `AppConfig.desktopDefaultSize` and `desktopMinSize` are both `1080x880`
  (was `1160x1000` with a `1000x780` minimum).
- `main_windows.dart` and `WindowController` call `setResizable(false)` and
  `setMaximumSize(...)`, and the title bar no longer draws a maximise button.
  Returning from the tray panel does not re-enable resizing.
- Saved window width/height are ignored on purpose - otherwise the old
  oversized geometry would come straight back from `settings.json`. Position is
  still restored.
- Connect button 232 -> 248.
- `WorldStage` gained `zoomBoost`; the home map passes `1.35`, so the dots fill
  the card instead of leaving empty bands above and below.

## 4. Rounded logo everywhere, centred tray icon

`desktop/packaging/make-icons.ps1`.

Every frame now clips the logo through a rounded-rect `GraphicsPath` (radius
28% of the tile), so the tray, the taskbar, Alt-Tab and the Programs list all
get a rounded icon instead of a hard square.

The off-centre tray icon had a specific cause: glow frames shifted the artwork
up *and* left by 4% of the icon size using one shared offset. The logo is now
centred and the status dot simply overlaps it.

Icons are regenerated by `build-all.ps1 -MakeIcons` and by the CI "Generate
Icons" step.

## 5. Real flags instead of emoji

`lib/widgets/flag_art.dart` (new), used by `FlagCircle`.

Windows has no colour emoji flag glyphs, so a regional-indicator pair degrades
to the bare letters - which is why the server pill showed "DE DE". The
extension's hand-built flag bodies (`extension/ui/flags.js`) are ported onto the
same 24x16 grid as painter primitives: ~60 flags, plus a violet wire-globe
fallback.

`resolveCountryCode()` accepts a code, an English country name, a city, or a
flag emoji (decoded from regional indicators), so every existing call site -
including the mobile app, which passes `countryFlag(code)` - keeps working with
no changes.

## 6. Orbits aligned with the connect button

`desktop_home_screen.dart`.

The bloom, the halo and the orbital rings are painted around the middle of the
map stage, but the button was placed at `Alignment(0, 0.10)`. The rings
therefore hung above it. The button is back at dead centre: one centre for
every layer.

## 7. "It still does not connect" - root cause

The log said `driver_unavailable` / "WireGuard driver files are missing".

`native/glukvpn-tunnel-service/src/tunnel.cpp` loads two DLLs at runtime:
`wireguard.dll` (WireGuardNT) and `tunnel.dll` (WireGuard's embeddable tunnel
service). The pipeline only ever downloaded the first one, and
`build-all.ps1` treated a missing file as a *warning*. Every build therefore
shipped a client that looked healthy and could never bring a tunnel up.

- `build-all.ps1` now downloads both into `native/.../vendor/amd64` (the
  embeddable service version is discovered from the download index, falling
  back to 0.5.3) and **throws** if either is still missing.
- `.github/workflows/build-desktop.yml` does the same and fails the job.
- `DesktopVpnController._humanise()` translates `driver_unavailable`,
  `service_unavailable` and `not_authenticated` into Russian/English text that
  tells the user what to do, instead of passing the service's English string
  into a Russian UI.

## 8. Start in the tray now works

`main_windows.dart` used to hide the window only when `startHidden && startMinimized`,
and `startHidden` requires the `--hidden` argument that only the autostart entry
passes. Launching by hand always showed the window. It is now
`startHidden || saved.startMinimized`, and the same value is handed to
`WindowController.attach(startHidden:)`.

## 9. Advanced settings from the extension

`desktop_settings_screen.dart`: the Advanced block gained the extension's
"for developers" facts - control API, web dashboard, service name - as
read-only rows, plus `#btn-reset` as "Reset advanced" (always-direct routes, MTU
and the split-tunnelling app list).

The endpoints are deliberately **not** editable: the brief forbids a
user-facing API URL field, and an editable endpoint in a VPN client is a
phishing vector. The extension needs one only because it has no installer.

## 10. Account and devices, like the extension

- Order: this device, then active devices by last seen, then revoked ones.
- Every row carries a badge: `THIS DEVICE` / `ACTIVE` / `REVOKED`.
- The subtitle follows `.d-sub`: platform, then one status fact - revoked,
  online (with the node name), or last seen.
- "Revoke" is a text action in danger colour, hidden for the current device and
  for already revoked ones (the API rejects both).
- The counter above the list stays `used / max`, as in the extension.

## 11. New sign-in screen

`desktop_login_screen.dart`, rebuilt as a two-column layout in the spirit of the
Cloudflare screenshot:

- **Left**: logo, title, "Continue on the website" (the extension's
  `#btn-site-login`, opens vpn.gluk.tech), identifier + password with the same
  validation rules as the mobile app, sign-in button, "or continue with" and the
  Telegram / Google buttons (still gated by `AppConfig.telegramSignInEnabled` /
  `googleSignInEnabled`, shown disabled with a "soon" tooltip so the layout does
  not jump later).
- **Right**: a violet gradient panel with the product's own rotating
  `DottedWorld` globe, orbital arcs and three one-line selling points.

Below 860 px the brand panel is dropped and the form takes the window.

## Rebuild

```powershell
powershell -ExecutionPolicy Bypass -File desktop\packaging\build-all.ps1 -Channel prod -Installer -MakeIcons
```

`-MakeIcons` is required this time: the rounded icons are generated by that
script.

The window size changed, so the first launch may still hold the old geometry
from `%APPDATA%\GlukVPN\settings.json`; width and height are now ignored, so
nothing needs to be deleted.
