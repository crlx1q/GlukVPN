# Раунд 10 — WFP Kill Switch, показ окна, PROD-регистрация, Android

Ветка: `desktop/beta`. Предыдущий отчёт: `FIXES-ROUND-9.md`.

Коротко: в Windows починен интернет внутри туннеля, окно перестало застревать
невидимым, регистрация на сайте больше не зависит от канала, а Android-клиент
получил регистрацию, восстановление, экран «Аккаунт», баннер обновлений и

## БЛОК 1. Сеть Windows

### 1.1. Wintun и WFP

Главная причина «Без доступа к Интернету» найдена, и это не то, что было
написано в ТЗ. Разбор по пунктам.

| Файл | Изменение |
| --- | --- |
| `native/.../src/wfp.cpp` | `PermitInterface` хранит LUID в именованной `UINT64 luidValue`, `reinterpret_cast` убран |
| то же | `PermitInterface` считает добавленные фильтры и возвращает `false` с `killswitch_failed`, если не добавился ни один. Раньше функция могла «успешно» ничего не сделать |
| то же | `EnableKillSwitch` добавил **входящий** разрешающий фильтр для DHCP (`FWPM_CONDITION_IP_LOCAL_PORT` = 68) на `FWPM_LAYER_ALE_AUTH_RECV_ACCEPT_V4` |
| то же | `EnableKillSwitch` добавил **входящий** разрешающий фильтр для эндпоинта VPN на том же слое. Без него block-all съедал ответы handshake — исходящий пакет уходил, ответ не приходил, туннель «поднимался» и молчал |
| `native/.../src/tunnel.h` | объявлен `PermitTunnelInterface(uint64_t)` и добавлен `std::atomic<uint64_t> permittedLuid_{0}` |
| `native/.../src/tunnel.cpp` | новый `Tunnel::PermitTunnelInterface`: идемпотентный, не делает ничего при неактивном kill switch, при ошибке оставляет `permittedLuid_ = 0`, чтобы следующий опрос статуса повторил попытку |
| то же | вызов из `RefreshFromDriver` сразу после чтения `stats.adapterLuid` |
| то же | `permittedLuid_.store(0)` в `ReleaseNetworkLocks` и в `Down()` |

**Что в ТЗ было неточно (три расхождения, все важные).**

1. **Указанная строка не была живым багом.** В `FWP_CONDITION_VALUE0` поле
   `conditionValue.uint64` объявлено как `UINT64*` — передача указателя это
   контракт API, а не ошибка. Параметр `luid` передаётся по значению и живёт
   дольше всех четырёх вызовов `FwpmFilterAdd0`, так что висячего указателя
   там не было. Код всё равно приведён к виду из ТЗ (именованная `UINT64`),
   потому что читается он теперь честнее.
2. **Настоящий баг — тот, что описан в первом абзаце ТЗ:** `PermitInterface`
   действительно вызывался только из `split_tunnel.cpp`, то есть в режиме Full
   Tunnel трафик внутри Wintun блокировался. Это исправлено.
3. **«Сразу после создания адаптера и запуска воркера» — так нельзя.** Воркер
   это отдельный процесс `glukvpn-wg.exe`, который `Tunnel::WorkerMain`
   запускает через `CreateProcessW`; адаптер Wintun создаёт он, асинхронно. На
   момент возврата из `Up()` адаптера ещё нет и LUID нечего читать. Поэтому
   разрешение ставится в `RefreshFromDriver` — это первый момент, когда
   `wg::ReadPeerStats` отдаёт `adapterLuid`, и попытка повторяется на каждом
   опросе статуса, пока не удастся.
4. **Пункт 1.1.3 уже был выполнен.** `Wfp::Instance().DisableKillSwitch()` в
   `Tunnel::Down()` стоял и раньше, плюс есть самолечение в `Up()`, `Status()`
   и `WorkerMain`. Добавлен только сброс `permittedLuid_`.

### 1.2. Окно на Windows

| Файл | Изменение |
| --- | --- |
| `flutter-client/lib/desktop/state/window_controller.dart` | приватный `_surface()`: `isMinimized() → restore()`, затем `show()`, `focus()`, и для главного окна короткий `setAlwaysOnTop(true/false)`, чтобы вытащить окно на передний план. `showMain()` и `showMini()` теперь идут через него |
| то же | публичный `surfaceForSecondInstance()` — открывает именно главное окно, а не панель 320 px |
| `flutter-client/lib/desktop/services/single_instance.dart` | `claim()` пробует `Global\` мьютекс, а при отказе (нет `SeCreateGlobalPrivilege`) падает на `Local\`. Раньше при нулевом хендле блокировка «открывалась» и каждая копия считала себя первой |
| то же | событие `Local\GlukVPN.Desktop.ShowWindow` (auto-reset): `armShowRequests()`, `consumeShowRequest()`, `signalShowRequest()` |
| `flutter-client/lib/main_windows.dart` | вторая копия сначала просит работающую показать себя, потом уже дёргает окно снаружи. Первая копия армирует событие и опрашивает его таймером на 400 мс, отменяя в `dispose()` |

Почему просьба, а не только `ShowWindow` снаружи: только сам процесс знает,
развёрнута ли у него мини-панель или главное окно, а человек, повторно
запустивший ярлык, хочет главное.

## БЛОК 4. Android

| Файл | Что это |
| --- | --- |
| `lib/services/register_api.dart` | новый публичный клиент: `/api/auth/register/start\|resend\|verify-email`, `status`, `/api/auth/config`, `/api/auth/password/forgot\|reset`. Регистрация жёстко на prod (то же правило, что и на сайте), восстановление — на активном канале |
| `lib/screens/register_screen.dart` | `RegisterScreen`: 3 шага (Email+пароль → 6-значный код → `@glukvpnbot`) с индикатором шагов, повторной отправкой кода (кулдаун 30 с) и опросом статуса раз в 3 с. Ник бота берётся из `telegramUrl`, а не прошит. `RecoverScreen`: 2 шага, выбор канала email/Telegram |
| `lib/screens/account_screen.dart` | профиль, подписка, активные сессии с «Отозвать», отдельный блок отозванных, pull-to-refresh |
| `lib/widgets/update_banner.dart` | баннер новой версии; обязательное обновление нельзя скрыть |
| `lib/main.dart`, `lib/app.dart` | `UpdateChecker` создаётся, отдаётся в провайдер и запускается; `_UpdateLayer` рисует баннер над всеми экранами и уступает место offline-баннеру |
| `lib/screens/login_screen.dart` | кнопки «Create an account» и «Forgot your password?» вместо прежней фразы «идите на сайт» |
| `lib/screens/settings_screen.dart` | `StatelessWidget` → `StatefulWidget`; пункт «Account»; 5 нажатий по строке версии за 3 с открывают Channel + Diagnostics |

**Решения, которые стоит знать.**

* **Капчи на Android нет.** У Turnstile нет Flutter-виджета, а тащить WebView
  ради одного чекбокса хуже самой проблемы. Сервер относится к отсутствующему
  токену так же, как для десктопа, а лимиты на `/api/auth/register/*` работают.
* **«Активные сессии» — это устройства.** На сервере нет отдельного объекта
  «сессия», которым мог бы управлять пользователь: сессия принадлежит
  зарегистрированному устройству, и именно отзыв устройства закрывает туннель и
  убирает peer с ноды. Рисовать список сессий, который нельзя отозвать, рядом со
  списком устройств, который можно, значит учить не доверять кнопкам.
* **Ссылку на бота приходится копировать, а не открывать.** В проекте нет
  `url_launcher`; добавлять нативный плагин ради одной кнопки не стал. Экран
  показывает и ссылку, и код, обе с кнопкой копирования.
* **Dev-меню: счётчик нажатий в памяти, выбор канала — на диске.** Само окно —
  дверь, а не настройка, поэтому оно не запоминается. А вот канал сохраняет
  `ChannelController`: сборка, забывающая на каждом старте, к какому контуру она
  подключена, для тестирования бесполезна.

## Что не сделано

1. **Ключик VPN в быстрых настройках Windows 11 (из раунда 9).** Записи в
   Quick Settings берутся только из телефонной книги RAS (IKEv2/L2TP/SSTP/PPTP).
   Туннель WireGuard/Wintun там появиться не может — ни у нас, ни у Proton,
   который показывает там свой профиль IKEv2, а не WireGuard. Варианты описаны
   в §5 отчёта раунда 9; ни один не реализован.
2. **`site/en/login/index.html` не переведён на три режима.** Английская
   страница по-прежнему только вход: у неё нет разметки `[data-auth-pane]`,
   `[data-reg-step]` и слотов капчи, а без них подключение `register.js`
   ничего не даст. Нужен отдельный проход по файлу, как в раунде 9 для RU.
3. **`site/en/app/index.html`** не получил блок «Безопасность аккаунта»
   (`.sec-actions` + `account.js`) — то же самое, отдельная работа по разметке.
4. **Локализация остатков ошибок** в `site/assets/js/app.js` и в
   `_humanise()` Flutter-клиента не доделана.
5. **Ничего не собрано.** C++, Go и Flutter в этой среде собрать нечем:
   разрешены только команды git и npm. Каждый файл дописан до конца, но
   компиляцию и прогон на живой Windows надо сделать руками.
